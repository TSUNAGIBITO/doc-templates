## 1. 本書の目的

シカクルMVPの非機能要件を定義する。**スモールスタート前提のため、「初期に妥協する水準」と「妥協しない水準」を明示**する。
数値は初期の仮置き（要確認事項 E-1 で事業計画に合わせて確定）。

## 2. 非機能要求グレード（大項目）

| # | 大項目 | 概要 | 重要度（MVP） |
|---|--------|------|--------|
| A | 可用性 | 稼働率・障害時の継続性 | 中（マネージド既定に委譲） |
| B | 性能・拡張性 | 応答時間・スループット・拡張余地 | 中 |
| C | 運用・保守性 | 監視・バックアップ・保守作業 | 中 |
| D | 移行性 | 移行方式・移行期間 | 低（新規のため） |
| E | セキュリティ | 認証・認可・暗号化・監査 | **高（妥協しない）** |
| F | システム環境 | 対応ブラウザ・アクセシビリティ・法令 | 中 |

## 3. 可用性

> 方針：**自前の冗長化は作らず、Vercel/Supabase/StripeのマネージドSLAに委譲**。MVPは可用性より反復速度を優先。

| 項目 | 要件（MVP） |
|------|------|
| 稼働時間 | 24/365（ベストエフォート、計画停止を除く） |
| 稼働率 | 目標 99.5% 程度（マネージド基盤依存、SLA契約なし） |
| RTO | 数時間（基盤復旧＋再デプロイ） |
| RPO | Supabaseの日次バックアップ（Proは Point-in-Time Recovery 検討） |
| 冗長構成 | マネージド既定（自前多重化なし）。M2で必要に応じSLO設定・冗長化。 |

## 4. 性能・拡張性

| 項目 | 要件（MVP・仮） |
|------|------|
| オンライン応答時間 | 主要画面 p95 で 2秒以内 |
| 受験の同時接続 | 初期 数百ユーザ同時（バズ時は劣化許容、要監視） |
| ピーク時受験 | 初期 数千件/日 想定。急増トリガーでM2の負荷対策へ |
| データ増加見込み | 回答/イベントログが主。年数百万〜行を想定し**スキーマは最初から正規化** |
| 拡張余地 | 採点・集計の非同期化（キュー/ワーカー）は M2 で分離可能な設計に留意 |

## 5. 運用・保守性

| 項目 | 要件（MVP） |
|------|------|
| 監視 | Sentry（エラー）＋ Vercel/Supabase の基本メトリクス、決済失敗アラート |
| バックアップ | Supabase 自動バックアップ（Proで保持期間延長/PITR） |
| デプロイ | GitHub Actions＋Vercel。プレビュー環境でレビュー |
| ログ保管 | 監査ログ（認証/決済/認可）は最低1年。個人情報はログに残さない |
| 定期保守 | 依存関係の自動更新（Dependabot/Renovate）、月次で脆弱性レビュー |

## 6. 移行性

| 項目 | 要件 |
|------|------|
| 移行方式 | 新規サービスのため既存データ移行なし |
| 可搬性 | Postgres/Stripe/OIDC等の標準に寄せ、将来の基盤移行コストを低減（要件定義書 5.3） |

## 7. セキュリティ

> 詳細はセキュリティ要件定義書（SEC-SKR-001）参照。**MVPでも妥協しない領域**。

| 項目 | 要件 |
|------|------|
| 認証方式 | OAuth/OIDC標準、パスキー(WebAuthn)/MFA提供、管理系はMFA必須 |
| 認可 | RBAC＋**Supabase RLS**（作成者/受験者/運営の行レベル権限）。RLSはテスト必須 |
| 通信暗号化 | TLS強制（HSTS）。混在コンテンツ禁止 |
| 保存データ暗号化 | マネージドDB既定の保存時暗号化。機微データはログ/URL非保持 |
| 決済 | カード非保持（Stripeトークン化）＝PCI DSS SAQ-A。3-Dセキュア |
| 監査ログ | 認証・認可・決済イベントを取得・改ざん防止 |
| 準拠 | OWASP Top 10:2025、個人情報保護法（2026改正動向）、（本人確認導入時）番号法・犯収法 |

## 8. システム環境

| 項目 | 要件 |
|------|------|
| 設置環境 | クラウド（Vercel＋Supabase）。オンプレなし |
| 対応ブラウザ | Chrome/Edge/Safari 最新2世代、スマホブラウザ（レスポンシブWeb） |
| 端末 | MVPはWebのみ（ネイティブアプリは Could / CR-004） |
| アクセシビリティ | 主要導線で最低限のコントラスト/キーボード操作を確保（JIS X 8341-3 AA準拠は将来目標） |

## 9. 非機能要件一覧（測定方法）

| 要件ID | 項目 | 要件値 | 測定方法 | 確認テストID |
|--------|------|--------|----------|--------------|
| NFR-SKR-001 | オンライン応答時間 | p95 2秒以内 | 性能計測 | TS-P-001 |
| NFR-SKR-002 | 認可（RLS） | 他者データにアクセス不可 | RLSテスト/権限テスト | TS-S-001 |
| NFR-SKR-003 | 決済PCI | SAQ-A（カード非保持） | 構成レビュー | TS-S-002 |
| NFR-SKR-004 | 監査ログ | 認証/決済イベント記録 | ログ確認 | TS-S-003 |
| NFR-SKR-005 | 稼働率 | 99.5%程度（ベストエフォート） | 監視集計 | — |

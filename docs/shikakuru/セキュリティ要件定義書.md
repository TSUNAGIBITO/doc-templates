## 1. 本書の目的

シカクルMVPのセキュリティ要件を定義する。スタートアップのスモールスタートであっても、
**決済・個人情報・2サイドの権限分離を扱うため、以下の最低ラインは初日から死守する**。
基準は2026年時点の最新（OWASP Top 10:2025、個人情報保護法改正動向、PCI DSS 4.0.1）を踏まえる。

## 2. 準拠基準・ガイドライン

| No | 基準・ガイドライン | 適用範囲 |
|----|--------------------|----------|
| 1 | OWASP Top 10:2025 | アプリ全体の設計・実装 |
| 2 | PCI DSS 4.0.1（SAQ-A 相当） | 決済（カード情報はStripeへ委譲・非保持） |
| 3 | 個人情報保護法（令和8年改正動向：課徴金導入・罰則強化） | 個人データの取扱い全般 |
| 4 | 安全なウェブサイトの作り方（IPA） | 実装 |
| 5 | 番号法・犯収法（JPKI eKYC導入時のみ） | 将来の本人確認機能 |

## 3. 認証・認可

| 項目 | 要件 |
|------|------|
| 認証方式 | OAuth/OIDC標準。メール＋パスワード／ソーシャル／**パスキー(WebAuthn)** |
| MFA | 運営・管理アカウントは**MFA必須**。エンドユーザーにもパスキー/MFAを提供 |
| パスワードポリシー | 認証プロバイダ（Clerk/Supabase Auth）の推奨に準拠。漏えいパスワード検知を有効化 |
| アカウントロック | 総当たり対策（レート制限・ロック）をプロバイダ機能で有効化 |
| 認可（最重要） | **RBAC＋Supabase RLS**。作成者は自検定のみ、受験者は自データのみ、運営は管理権限。**OWASP A01対策の中核** |
| 認可のテスト | **RLSポリシー・権限境界を自動/手動テストで検証**（設定ミスは即情報漏えい） |
| セッション | タイムアウト・固定化対策・再認証（プロバイダ既定＋設定） |

## 4. 通信・データ保護

| 項目 | 要件 |
|------|------|
| 通信暗号化 | 全通信 **TLS 強制（HSTS）**。弱い暗号スイート禁止。混在コンテンツ禁止 |
| 保存データ暗号化 | マネージドDB（Supabase）の保存時暗号化を利用。機微データは列レベル暗号化を検討 |
| 鍵・秘密情報管理 | APIキー/DB資格情報はコードに埋めず、Vercel/Supabaseの環境変数・Secretsで管理。**GitHub Secret Scanning／pre-commit** でコミット防止 |
| データ最小化 | 個人情報は**ログ・URL・クエリに含めない**。非本番環境はダミー/マスキングデータ |
| 個人番号 | **マイナンバー（個人番号12桁）は取得・保存しない**（番号法。本人確認はJPKIで実施し外部eKYCに委譲） |

## 5. アプリケーションセキュリティ（OWASP Top 10:2025）

| 脅威 | 対策 |
|------|------|
| A01 アクセス制御の不備 | RLS＋アプリ層認可の二重化、IDOR対策、SSRF対策。**最優先** |
| A02 設定ミス | 既定の安全設定、不要機能無効化、権限最小化、CSP設定 |
| A03 サプライチェーン | **Dependabot/Renovate**で依存自動更新、`npm audit`/SCA、lockfile固定、ビルド改ざん対策 |
| A04 暗号の不備 | TLS/保存時暗号化、機微データの適切な取扱い |
| A05 インジェクション | ORM/プレースホルダ、入力検証、出力エスケープ |
| A06 安全でない設計 | 脅威モデリング（決済/権限分離）、レート制限 |
| A07 認証の不備 | パスキー/MFA、漏えいパスワード検知、セッション管理 |
| A08 完全性の不備 | 署名付きWebhook（Stripe署名検証）、CI/CDの完全性 |
| A09 ログ・アラート不備 | 監査ログ＋Sentryで異常検知・通知 |
| A10 例外条件の不備 | エラー時の安全側動作、機密情報を含まないエラーメッセージ |
| XSS/CSRF | 出力エスケープ・CSP、CSRFトークン/SameSite Cookie |

## 6. 決済セキュリティ（PCI DSS）

| 項目 | 要件 |
|------|------|
| カード情報 | **自社サーバに一切通さない**。Stripe Checkout/Elementsでトークン化 → **SAQ-A** |
| 保持情報 | Stripeのトークン/顧客IDのみ保持（PAN・CVC非保持） |
| 決済ページ完全性 | 外部スクリプトの完全性管理・変更検知（PCI 6.4.3 / 11.6.1） |
| 3-Dセキュア | 有効化（Stripe） |
| Webhook | Stripe Webhookは**署名検証**必須、冪等処理 |

## 7. ログ・監査

| 項目 | 要件 |
|------|------|
| 取得対象 | 認証・認可・決済・返金・検定公開/停止・運営操作 |
| 監査ログ項目 | 日時・利用者・操作・対象・結果・IP（個人情報は最小化） |
| 改ざん防止 | 追記専用・アクセス制限 |
| 保管期間 | 監査ログ 1年以上 |

## 8. インシデント・個人情報保護対応

| 項目 | 内容 |
|------|------|
| 検知・連絡体制 | Sentryアラート → 対応担当。最小限のインシデント対応手順を用意 |
| 漏えい時報告 | 個人情報保護委員会への報告・本人通知体制（改正法の合理化動向を反映） |
| 法対応 | 利用目的の明示、安全管理措置、第三者提供の同意/記録、プライバシーポリシー整備 |
| 未成年 | 改正で強化される16歳未満・顔/生体データはMVPで**扱わない設計**に寄せる |

## 9. セキュリティ要件一覧（確認方法）

| 要件ID | 項目 | 要件 | 確認方法 |
|--------|------|------|----------|
| SEC-R-001 | 通信暗号化 | TLS強制/HSTS | 設定確認・診断 |
| SEC-R-002 | 認証 | パスキー/MFA、管理系MFA必須 | テスト |
| SEC-R-003 | 認可 | RLS＋アプリ層で他者データ不可 | 権限/RLSテスト |
| SEC-R-004 | 決済 | カード非保持（SAQ-A） | 構成レビュー |
| SEC-R-005 | Webhook | Stripe署名検証 | コードレビュー/テスト |
| SEC-R-006 | 秘密情報 | Secrets管理・コミット防止 | Secret Scanning |
| SEC-R-007 | 依存関係 | 自動更新・監査 | Dependabot/audit |
| SEC-R-008 | 個人番号 | 取得・保存しない | 設計レビュー |

## 10. MVPで「割り切る（当面実施しない）」セキュリティ項目

> リスクを認識した上での意図的な範囲外。要件定義書 ④4.3・⑤ と整合。

| 項目 | 割り切りの理由 | 顕在化トリガー |
|------|--------------|--------------|
| マイナンバー/JPKI本人確認 | 番号法・eKYCコスト。エンタメ検定に不要 | 採用/国家資格連動・エンプラ導入 |
| 受験の高度な不正防止（顔監視・厳格ランダム化） | エンタメ用途で費用対効果が低い | 資格性の高い検定の提供 |
| SOC2/ISMS/Pマーク等の第三者認証 | 取得コスト大 | エンプラ/上場準備 |
| 専用WAF/高度DDoS対策 | マネージド既定で当面代替 | 大規模トラフィック/攻撃 |
